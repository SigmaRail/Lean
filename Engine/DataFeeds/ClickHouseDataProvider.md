# ClickHouse Bar Materialization Intent

## Purpose

This provider is the **bar materialization** layer for LEAN integration with ClickHouse.

It is responsible for:

- Building LEAN-compatible daily equity zip files on demand
- Validating whether an existing zip on disk is still fresh enough
- Writing refreshed zip artifacts and metadata when needed
- Serving the generated bytes through LEAN's composite data-provider pipeline

## Important separation of concerns

This provider should **not** be used for universe screening.

That job belongs to the universe-selection classes under:

- `Lean/Common/Data/UniverseSelection/`

## Intended flow

1. LEAN asks for a data source such as an equity daily zip.
2. The composite data provider tries the on-disk provider first.
3. If the artifact is missing or stale, the ClickHouse provider rebuilds it from ClickHouse.
4. The rebuilt zip is cached in memory and optionally materialized to disk.

## Why this exists

The goal is to keep LEAN's bar data path predictable and efficient:

- one ticker archive at a time
- range-aware freshness checks
- explicit zip generation from ClickHouse
- no universe filtering logic mixed into this provider
